# AGENTS.md

Static personal landing page: Astro 7, Tailwind CSS 4 (via `@tailwindcss/vite`),
React 19 islands, Bun runtime, fully prerendered (`output: 'static'`). `zh_CN`
is the default locale, `en_US` the second one. All copy, navigation and RSS feed
config live in `i18n/zh_CN.json` and `i18n/en_US.json`; components receive that
data as props. Before editing anything, read the schema that governs those
files: `src/content.config.ts`.

## Repository map

- `src/pages/` — routes. `index.astro` redirects to `/${defaultLocale}/`;
  `404.astro` is the root 404 page; every locale page lives in
  `src/pages/[lang]/` and is generated for all locales via `getStaticPaths()`.
- `src/components/ui/` — Astro static components (HeaderBar, Hero, WebsiteItem,
  FeaturedPostItem, Footer, ThemeToggle, LanguageSwitcher, ContactCards,
  ContactServices, sections). Zero client-side JS by default.
- `src/components/react/` — React islands. Only `ContactForm.jsx` is mounted on
  the contact page with `client:idle`. All other pages (index, about, 404) are
  100% Zero-JS.
- `src/layouts/BaseLayout.astro` — the only layout: SEO/meta, OG image
  transform, theme bootstrap, GA, global CSS and fonts, native underline effect
  script.
- `src/lib/i18n.ts` — `locales`, `localeConfig` and helpers
  (`getEntry('i18n', id)`); the source of the `Locale` type.
- `src/lib/localImages.ts` — unified local image resolver (`getLocalImage` /
  `getWebsiteImage`) over `src/assets/img/`.
- `src/content.config.ts` — Zod schema for the i18n content collection (`glob`
  over `./i18n`).
- `src/data/rss-posts.json` — generated by `scripts/fetch-rss.bun.js`, committed
  to git.
- `docs/nginx-config-example.conf` — nginx serving reference (orphaned; not
  referenced by README or CI).

## Sources of truth

- `README.md` / `README_zh.md` — env vars, component table, adding a language,
  deployment. Read the "Adding a New Language" section before touching locale
  setup.
- `.github/workflows/deploy.yml` — the only deployment path (SSH into the
  server). CI runs no tests.

## Commands

```bash
bun install
bun run dev          # dev server (Bun runtime)
bun run build        # prebuild hook re-fetches RSS into src/data/rss-posts.json first
bun run preview      # serve the built site
bun run type-check   # tsc --noEmit
bun run lint         # astro check
bun run fetch:rss    # manual RSS refresh only; requires the Bun runtime
```

- `dev:node` / `build:node` are the same two commands with `NODE_OPTIONS`
  cleared.
- Run Prettier only on files you touched (`npx prettier --write <file>`).

## Architecture / invariants

- Copy comes from data: pass text in via props from the i18n collection. Don't
  hardcode visible strings in components (BaseLayout's default props are English
  fallbacks — don't extend that).
- `zh_CN.json` and `en_US.json` must satisfy the same schema and keep the same
  key set (they do today). A missing key makes `getI18n()` fall back to `zh_CN`
  instead of erroring.
- Adding a locale means three coordinated edits: `astro.config.mjs`
  (`i18n.locales` + `sitemap.i18n.locales`), `src/lib/i18n.ts` (`locales`,
  `localeConfig`), and `i18n/<locale>.json`.
- Dark mode is class-based (`@custom-variant dark (&:where(.dark, .dark *));`;
  `BaseLayout.astro` toggles `.dark` on `<html>` before hydration from
  `localStorage`/`prefers-color-scheme`). Use the semantic tokens `paper`,
  `raised`, `ink`, `inksoft`, `hairline`, `vermilion` (declared via `@theme` in
  `src/styles/global.css` that flip under `.dark`). Don't introduce raw palette
  colors or per-component `dark:` variants.
- Local images go in `src/assets/img/` (website cards in
  `src/assets/img/websites/`) and are resolved through `getLocalImage()` so
  `astro:assets` optimizes them.
- Keep the site fully prerendered.
- React islands: only `ContactForm.jsx` is hydrated with `client:idle`. The rest
  of the site is zero JavaScript.
- Imports use the aliases in `tsconfig.json` (`@components/ui`,
  `@components/react`, `@layouts`, `@lib`, `@data`, `@styles`, `@/*`), not
  relative paths into `src/`.

## Development rules

- Prettier: printWidth 100 (CSS 120, JSON 80/4-space), single quotes, no arrow
  parens.
- New files follow the repo's JSDoc header convention (`@fileoverview`,
  `@module`, `@since`) with Chinese comments; write new content in Chinese for
  `zh_CN.json` and English for `en_US.json`.
- No test framework exists. Don't introduce one unasked.

## Validation

Minimum after a change:

- `bun run type-check`
- `bun run lint`
- `bun run build` for anything under `src/` — including i18n JSON edits, which
  is how schema violations surface.

## Safety

- Pushing to `main` deploys to production (the workflow resets the server
  checkout to `origin/main` and rebuilds). Treat `main` as the release branch.
- `.env` holds live EmailJS credentials and is gitignored; only `.env.example`
  is tracked. Don't commit `.env` or copy its values into docs or code.
- `src/data/rss-posts.json` is generated but tracked: regenerate it
  (`bun run fetch:rss` or `bun run build`) rather than hand-editing, and expect
  `bun run build` to modify it when a feed has new posts.
- `bun run clean` removes `node_modules`, `dist/` and `.astro/`;
  `bun run reinstall` runs it plus `bun install`. Both are heavy — use only when
  asked.
- `scripts/fetch-rss.bun.js` exits non-zero without Bun, and warns instead of
  failing when an i18n file can't be read (its `prebuild` hook swallows failures
  with `|| true`), so a failed feed fetch still yields a successful build.
